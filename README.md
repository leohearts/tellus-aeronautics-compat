# Tellus Aeronautics Compat

Three fixes for running [Create Aeronautics](https://modrinth.com/mod/create-aeronautics)
(Sable) on a [Tellus](https://modrinth.com/mod/tellus) world: airships keep their lift,
assembled vehicles stop corrupting the server, and a hot air balloon that is not airtight
stops walking off into the world.

## 1. Air pressure

Sable's default curve is `exp(-0.004 * (y - sea level))`. That `0.004` is tuned for vanilla
384 block tall worlds, where pressure halves every 173 blocks. Tellus worlds are orders of
magnitude taller — a mountain range can start above y=1000 — so an airship loses all lift
long before it gets anywhere useful.

On server start the mod walks every dimension, picks out the ones generated by Tellus, reads
the world's own `EarthGeneratorSettings` and rebuilds the pressure curve from them using a
real atmospheric scale height of 8500 m. The result is registered with Sable at a priority
above any datapack-provided curve.

The block to metre mapping is delegated to Tellus' own `TerrainHeightTransform`, so it stays
correct across Tellus versions and handles the `height_scale / world_scale` ratio, the
latitude correction, and the experimental height increase. Dimensions Tellus does not
generate are left untouched.

## 2. Sub-level plots

Sable does not put assembled vehicles in a separate dimension. It keeps them in a reserved
chunk grid of the overworld: `DEFAULT_ORIGIN` 10000 plots of `DEFAULT_LOG_PLOT_SIZE` 7, i.e.
chunks 1280000..1296255, blocks **20480000..20740095**.

Tellus' world is a Mercator projection clamped to ±20037508 blocks. Worse, while the
experimental height increase is on, Tellus replaces `BlockPos.asLong/getX/getY/getZ` with a
dense 64 bit layout that clamps X/Z to that same range, and the layout is already at the
64 bit limit, so it cannot be widened. Every block of every Sable plot therefore collapses
onto the world edge, which is what breaks Sable's collisions and physics, and any chunk out
there makes Tellus' chunk generator throw outright.

This mod moves the grid to plot 9000: blocks **18432000..18694143**, over open Pacific and
far from anywhere players build. Both the server and the client are patched, and they have to
agree, so install it on both sides.

Sub-levels that were saved at the old origin stay there and have to be assembled again.

## 3. Hot air balloon fills

A hot air burner finds its envelope by flooding the air around it. `BalloonBuilder` walks one
Y level with a breadth first search and recurses on the block above every position it accepts,
and nothing bounds either the recursion or the search: a burner with no airtight envelope, or
one whose envelope has a gap, is walked to the top of the world.

On a vanilla world that is a few hundred levels. Tellus' build height is 10448, so the client's
render thread dies with a `StackOverflowError` while ticking the burner, and a dedicated server
stalls inside one tick. The mod caps the recursion at 128 levels and each level at a 48 block
radius around the burner, and aborts the fill when either is reached. A real envelope is a few
dozen blocks across and tall, so neither cap is reached by a balloon that is actually enclosed;
one that is not gets logged once and fails to build instead of taking the game down.

| Loader | NeoForge 21.1+ |

| [Tellus](https://modrinth.com/mod/tellus) | 0.8+ |

## Do not install c2me

`c2me` drives chunk generation itself and bypasses Sable's `ServerChunkCache` hooks, which are
what hand out empty chunks for plot positions. With c2me the plot chunks get generated as real
terrain instead: on a Tellus world that means chunks outside the world, a thrown exception,
and a chunk system that never recovers — the server hangs until the watchdog kills it. The mod
logs a warning on startup if it sees c2me.

## Configuration

None. The pressure curve comes from the world's Tellus settings and the plot grid is a
constant.

## Building

```sh
./gradlew build
```

The two compile-time dependency jars are downloaded from the Modrinth CDN into `libs/` on
the first build and are not committed to the repository. The output jar lands in
`build/libs/`.
